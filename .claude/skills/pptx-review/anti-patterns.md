# AIっぽいスライドの検出基準

レビューで探すのは次の6カテゴリ。どれも「それ自体が悪」ではなく、**伝えたい内容の重みや読む順番と無関係に、全スライドへ一律にかかっている**ときに問題になる。指摘するときは、その資料でなぜ不要なのか（または何に置き換えるべきか）まで言えるものだけを出す。

兆候は「画像で見るとき」と「抽出 JSON / XML で見るとき」の両方で書いている。抽出 JSON は `scripts/extract.py` の出力で、図形ごとに `geometry`・`fill`・`line`・`effects`・`style`・`text` を持つ。

資料は画面と違い、表紙や章扉のように**中央寄せや大きな装飾が普通の場所**がある。表紙・章扉・締めの1枚は、本文スライドと同じ基準で裁かない。

## 1. 角丸カードの多用

### 兆候

- 本文の情報の大半が角丸の箱（`geometry.preset: "roundRect"`、`adjust.adj` が大きい）に入っている。箱の上にさらに箱や丸がある（カードの入れ子）。
- 性質の違う情報（説明文、数値、手順、比較）がすべて同じ形のカードに入っている。
- 白いカードを色付きの背景の上に置き、影で浮かせている（後述の 3 と組み合わさることが多い）。
- 数値を1つずつ小さなカードに入れて横に並べている（統計カードの3〜4列）。

### 計測の目安

- 本文スライドで `roundRect` が図形の多数を占める。
- `adjust.adj` が `val 10000` 以上（短辺の約1割以上の角丸）。
- カードの中身がスライド面積に比べて少なく、カードの下半分が空いている。

### 置き換えの方向

- 同種の項目の並びは、箱ではなく罫線・表・余白で区切る。
- 箱で囲むのは「他と区別すべき1つの塊」（結論、注意、引用）に限る。
- 角丸を使うなら小さく（`adj` を 0〜5000 程度）、または `rect` にする。
- 数値の並びは表にするか、いちばん言いたい数字1つを大きくして他は従える。

## 2. 飾りアイコン・絵文字

### 兆候

- タイトル、見出し、箇条書きの頭に絵文字（🚀✨💡📊🎯✅ など。抽出 JSON の `text.paragraphs[].emoji`）。絵文字は OS や PowerPoint のバージョンで見た目が変わり、資料の配色と馴染まない。
- 見出しごとに、色付きの丸や角丸四角（`ellipse` / `roundRect` に薄い塗り）の中にアイコンや絵文字を置いている。
- アイコンが見出しの文字と同じ意味を繰り返しているだけ（「セキュリティ」の横に鍵）。
- 箇条書きの記号を文字の「•」「・」「✔」で手打ちしている（`bullet` が `null` / `none` なのに本文が記号で始まる）。

### 置き換えの方向

- 絵文字は外す。強調が必要なら、文字の太さ・大きさ・位置で示す。
- アイコンは、文字だけでは伝わりにくいもの（操作手順の画面要素、地図の記号など）に限る。
- 見出しごとのアイコン付きカードは、見出しと本文だけの段組みか表にする。
- 箇条書きは段落の箇条書き設定（`a:buChar` / `a:buAutoNum`）を使い、手打ちの記号は外す。

## 3. グラデーション・影・意味のない色

### 兆候

- スライド背景やマスターの背景が紫〜青〜ピンクのグラデーション（`background.fill.type: "gradient"`、色が `6D28D9`・`7C3AED`・`8B5CF6`・`2563EB`・`3B82F6`・`EC4899` 付近）。
- 図形の塗りがグラデーション（`fill.type: "gradient"`）。
- ほぼすべての図形に影（`effects` に `outerShdw`、または `style.effectRef` が `1` 以上でテーマの影がかかっている）。光彩（`glow`）、ぼかし（`softEdge`）、3D（`scene3d` / `sp3d`）。
- アクセント色が何色もあり、色に意味が無い（項目ごとに色を変えているだけ）。
- 白抜き文字を濃いグラデーションの上に置き、全スライドが同じ派手な背景。

### 置き換えの方向

- 背景は白か、ごく薄い無彩色にする。濃い背景は表紙・章扉に限る。
- アクセント色は1つにし、いちばん伝えたいもの（結論の数字、比較で選ぶ側）にだけ使う。
- 影は外す。区切りは罫線か背景の明度差で示す。
- グラデーションは、社のブランド上の決まりが無い限り単色にする。
- 色を項目の区別だけに使っている場合は、無彩色＋ラベルにする。

## 4. 均一な余白と中央寄せ

### 兆候

- 本文スライドのタイトル・本文・箇条書きまで中央寄せ（`paragraphs[].align: "ctr"`）。
- 同じ大きさの図形が等間隔に3つ・4つ並ぶレイアウトが、何枚も繰り返される（「3つの特徴」「4つの数字」）。
- すべてのスライドが同じ構成（タイトル＋カード並び、またはタイトル＋箇条書き）で、内容によって形が変わらない。
- 文字の大きさの段階が少なく、どこから読むべきか分からない。いちばん言いたいことが他と同じ大きさ。
- スライドの結論（何が言いたいか）が、タイトルではなく末尾や小さな注記にある。

### 計測の目安

- 本文スライドの段落の大半が `align: "ctr"`。
- 図形の `box.w` が同じ値で、`box.x` が等間隔に並ぶグループが複数のスライドにある。
- 本文に使っている文字サイズの種類が1〜2種類しかない。

### 置き換えの方向

- 本文スライドのタイトルと本文は左揃えにする。数値の列は右揃え。中央寄せは表紙・章扉・一言だけのスライドに限る。
- タイトルは「何が言いたいか」の1文にする（「導入のメリット」ではなく「導入後3か月で作業時間が3分の1になった」）。
- 主と従を作る。いちばん言いたいことを大きく・左上に、補足は小さく・後ろに置く。
- 均等な並びは、内容が本当に同格のときだけにする。同格でなければ、順番や大小で差を付ける。

## 5. AI文体（スライド本文の文章）

### 兆候

- 中身の無い強調語: 「革新的」「画期的」「シームレス」「圧倒的」「次世代」「包括的」「最適化」「最大化」「加速」「エンパワー」「ソリューション」。
- 定型のつなぎ: 「さらに」「重要なのは」「〜を実現」「〜を可能に」「今ここに」「すべての人に」「〜の未来へ」。
- 主語と数字が無い主張（「業務効率を大幅に向上」— 何の業務が、何から何に）。
- 体言止めの箇条書きが同じ長さ・同じ形で並び、どれも同じ重み。
- 箇条書きが3つ・5つにきれいに揃えられ、内容の数と関係ない。
- 英語の直訳調（「〜することができます」「〜において」の多用）。

### 置き換えの方向

- 具体的な対象・数字・比較に置き換える。元の資料に数字が無いときは、数字を作らず、言い切りを弱めずに具体的な対象だけを書く（数字の捏造はしない）。
- 強調語は消し、事実だけを書く。
- 箇条書きは、並べる理由があるものだけにする。結論→理由の順に、文で書いたほうが伝わるときは文にする。
- 書き換えは元の意味を変えない。数字・固有名詞・社内用語は変えない。
