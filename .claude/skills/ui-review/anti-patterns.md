# AIっぽいUIの検出基準

レビューで探すのは次の4カテゴリ。どれも「それ自体が悪」ではなく、**情報の重みや操作の流れと無関係に、全体へ一律にかかっている**ときに問題になる。指摘するときは、その画面でなぜ不要なのか（または何に置き換えるべきか）まで言えるものだけを出す。

兆候は「CSS で見るとき」と「Tailwind で見るとき」の両方で書いている。このリポジトリのスタイリング手段は `project.md` を見ること。

## 1. 角丸カードの多用

### 兆候

- 画面の大半の情報が角丸の箱（CSS: `border-radius: 8px〜16px` ＋ `background` か `border`、Tailwind: `rounded-lg`〜`rounded-2xl`）に入っている。箱の中にさらに箱がある（カードの入れ子）。
- 一覧の各行、統計値、フォーム、説明文まで、性質の違う情報がすべて同じカードで包まれている。
- 境界線・背景色・影の3つを同時に使ってカードを区切っている。
- ボタン、入力欄、バッジ、カード、モーダルの角丸がすべて同じ大きめの値（共通トークン1つを全部に使っている）。
- 数値を1つずつ小さなカードに入れて横に並べている（「統計カード」の3列・4列）。

### 計測の目安

- 表示要素のうち `border-radius` ≥ 8px の要素が多数を占める。
- 背景か枠を持つ塊の入れ子が2段以上。
- 箱の中でも罫線で行を区切っていて、区切りが二重になっている。

### 置き換えの方向

- 同種の情報の並びは罫線・ゼブラ・余白で区切る（表、リスト）。
- 箱で囲むのは「独立して操作するもの」「他と区別すべき塊」に限る。
- 角丸は部品の大きさに応じて小さく（例: 入力欄・ボタン 4〜6px、塊 8px 以下、または0）。
- 共通トークンや共通クラスを変えると他画面に波及するので、まずはその画面専用のクラスで直す案も出す。

## 2. 飾りアイコン・絵文字

### 兆候

- すべての見出し、ラベル、統計値、メニュー項目の横にアイコンがある。
- アイコンが文字と同じ意味を繰り返しているだけ（「設定」の横の歯車、「メール」の横の封筒が全項目にある）。
- アイコンを色付きの丸や角丸四角の背景に入れている。
- 見出し、ボタン、空状態、ナビゲーションに絵文字（✨🚀📊🏠⚙️ 等）。絵文字は OS ごとに見た目が変わり、色も制御できないため、アプリの配色と馴染まない。
- アイコンライブラリ（lucide-react / heroicons など）が画面の至る所から import されている。

### 置き換えの方向

- アイコンは「文字なしで機能するもの」（閉じる、検索、メニュー、並べ替え、前後の移動）と、狭い場所での操作に限る。
- 下部タブのように「アイコン＋文字」が定着している場所は、消すのではなく、アプリの色に合う単色の線画（`currentColor`）にし、選択状態がアイコンと文字の両方に出るようにする。
- ラベルがある場所では、アイコンを外して文字の太さ・大きさ・位置で区別する。
- 空状態はイラストやアイコンではなく、次にやることを短い文とボタンで示す。

## 3. 紫青グラデ・影・意味のない色

### 兆候

- 背景、ヒーロー、ボタン、テキストに紫〜青〜ピンクのグラデーション（CSS: `linear-gradient(...)`, `background-clip: text`、Tailwind: `bg-gradient-to-*`, `from-purple-*`, `bg-clip-text`）。
- ほぼ全てのカード・ボタンに影（CSS: `box-shadow`、Tailwind: `shadow-md` 以上）。hover で影が強くなる・浮き上がる（`transform: translateY`）。
- ガラス風（`backdrop-filter: blur()` / `backdrop-blur` ＋ 半透明の背景）が重要でない場所に使われている。
- 主色が Tailwind の indigo / violet / purple の既定値そのまま。
- 意味を持つ色（収入＝緑、エラー＝赤など）が、グラフや飾りにも流用されていて、色を見ても意味が分からない。アクセント色が何種類も増えている。

### 置き換えの方向

- 色は無彩色の段階を主にし、アクセント色は1つ、使う場所を絞る（主ボタン、選択状態、リンク）。
- 意味を持つ色は、その意味を示す場所（金額の正負、状態の警告）にだけ使う。割合のバーなど長さで比べるものは無彩色でよい。
- 階層は影ではなく、背景の明度差・罫線・重なり順で示す。影は実際に上に浮くもの（メニュー、モーダル、ドラッグ中の要素）だけ。
- グラデーションはブランド上の理由がない限り使わない。
- ダークモードがあるなら、そちらでも同じ方針になっているかを見る。

## 4. 均一な余白と中央寄せ

### 兆候

- どのセクションも同じ余白（CSS: 同じ `padding` / `margin-bottom` / `gap`、Tailwind: `p-6` / `gap-6` / `space-y-6`）。関係の近いもの同士と遠いもの同士の間隔が同じ。
- ページ全体や数値が中央寄せ（CSS: `text-align: center` と `margin: 0 auto; max-width`、Tailwind: `text-center` と `mx-auto max-w-*`）。業務画面なのにランディングページのような構成。
- 同じサイズのカードをグリッド（CSS: `grid-template-columns: repeat(3, 1fr)`、Tailwind: `grid-cols-3`）で並べたレイアウトが繰り返される。
- 見出しや数字の大きさの段階が少なく、どこから読むべきかが分からない。いちばん見たい数字が他と同じ大きさ。
- 「ヒーロー → 3つの特徴カード → CTA」型の構成。
- 結論（合計・残り・状態）が一覧の末尾やスクロールしないと見えない位置にある。

### 計測の目安

- padding / margin / gap の値の種類が1〜2種類しかない。
- 主要コンテンツの text-align が center。
- 主要な情報の縦位置が、主ビューポートの見える範囲の外にある。

### 置き換えの方向

- 関係の近いものは詰め、区切りたいところは大きく空ける（余白に段階を作る）。
- 文章や表は左揃え、数値は右揃え（桁が揃うように `font-variant-numeric: tabular-nums`）。中央揃えは短い単独メッセージ程度に限る。
- 重要な情報を大きく・上に置き、補助情報を小さく・後ろに置く。均等なグリッドより、主と従のある配置にする。合計や結論は見出しの行に置く。
- 情報密度は利用頻度に合わせる。毎日使う画面は詰めてよい。
